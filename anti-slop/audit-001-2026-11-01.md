# Kodingu antislop audit 001

Date: 2026-11-01
Mode: AFTER (session override)
Scope: 15 pages, two themes, four widths, 120 renders, plus keyboard and interaction states.
Method: Playwright 1.64 headless Chromium against the local server with production CSP headers. Visual review of desktop and mobile screenshots. Static link and syntax checks.

## Verdict

Not delivery-clean. Three findings violate Hard Gate rules:

1. Preview iframes receive keyboard focus with no visible focus indicator. R-32. HIGH.
2. Mobile navigation hides every header destination behind a bare hamburger icon. R-03. HIGH.
3. Catalog course title links are 35px high at 768px. R-03. HIGH.

No contrast failures, page-level overflow, duplicate IDs, missing labels, dead links, or fabricated content were found. The rest of the Delivery Gate passes.

No product files were changed. The three findings below are proposals only.

## Findings

### 1. Preview iframes have no visible keyboard focus

Rule: R-32 (Keyboard Accessibility).
Priority: HIGH.
Where: `index.html` `#demo-frame`; the lesson editor `#editor-frame`; the same preview pattern is used by project and challenge editors.

Evidence:

- The home focus loop reaches `iframe#demo-frame` after the demo textarea. Computed focus style is `outline-style: none`, `outline-width: 3px`, `box-shadow: none`.
- The lesson editor at 390px reaches `iframe#editor-frame` with `tabIndex` 0, `outline-style: none`, `box-shadow: none`.
- The global `:focus-visible` rule in `base.css` does not render a ring on these replaced elements.
- Both previews are outputs, not form fields. They currently sit in the tab order between the editor and the next control.

Impact: a keyboard user tabs from the code editor into an invisible stop. The browser focus has moved, but the page gives no clue where it went. This is the R-32 failure: every focused element needs a visible indicator.

Fix options:

- If the preview is output only, add `tabindex="-1"` so it leaves the sequential tab order. Screen readers can still read the frame.
- If links inside the preview must stay keyboard reachable, add an explicit `iframe:focus-visible` ring, for example a 2px `--focus` outline with 2px offset, and verify it in both themes.
- Decide per preview. The lesson, project, and challenge previews are output; the home demo is also output. Removing the tab stop is the smaller change.

### 2. Mobile header hides all navigation behind a bare hamburger

Rule: R-03 (Mobile Responsiveness, Mobile Navigation: bare hamburger).
Priority: HIGH.
Where: `assets/js/app.js` header markup, `assets/css/app.css` navigation breakpoint at 860px.

Evidence:

- At 390px, `#site-nav` computes to `display: none`.
- The only visible navigation control is `#nav-toggle`: a 44x44 icon button.
- The text "Menu" exists only in a `.sr-only` span, clipped to 1px. Sighted users see the icon with no text hint.
- The hidden menu holds Catalog, Projects, Practice, Progress, and Start HTML. On inner pages these are the only header routes to the catalog and practice areas.
- The control itself works: it opens the menu, sets `aria-expanded="true"`, and Escape closes it and returns focus to the toggle.

Impact: the menu is functional and has an accessible name, but its discoverability depends on recognizing a hamburger. This is the pattern the mobile skill calls the bare hamburger, and it is the only way to reach several header destinations.

Fix options:

- Add a visible "Menu" label beside the icon at 860px and below. The 390px header has room; keep the target at least 44px high.
- Or keep the primary destinations visible in a compact bar and hide only secondary links.
- If the label is added, keep the icon and the label in one 44px target; do not duplicate the accessible name.

### 3. Catalog course title links are 35px high at tablet width

Rule: R-03 (Mobile Responsiveness, tap targets).
Priority: HIGH by rule tier. Practical scope is a secondary title link; the primary CTA already meets 44px.
Where: `catalog.html` course rows, `.catalog-title` in `assets/css/app.css`.

Evidence:

- At 768px, the three `.catalog-title` links measure 97x35, 59x35, and 145x35. Computed padding is `0px`; line-height is 34.56px.
- The 44px padding rule for this link applies only at `max-width: 720px`. The gap is 721px to 860px, the tablet range.
- At 390px the links have padding and pass.
- The "Start lesson" buttons on the same rows measure at least 44px and pass.

Impact: a tablet or touch laptop user gets a 35px-high target for opening a course. It works, but it is below the 44px minimum and inconsistent with the adjacent button.

Fix: extend the existing padding or add `min-height: 44px` with flex centering to `.catalog-title` up to 860px, or at all widths. Enlarge the hit area, not the type.

## Non-blocking notes

- Skip link: after activation, `document.activeElement` is `body`, not `main`. The hash becomes `#main`, and the next Tab lands on "Start the HTML course", so the bypass works. Adding `tabindex="-1"` to `main` and focusing it would make the landing explicit. Not counted as a finding.
- Shadow wording: DESIGN.md says the demo is the only shadow. The mobile menu also uses a shadow as an overlay elevation. The UI reason is valid; update the decision log or remove the shadow. Documentation only.
- CSP: `_headers` still includes `'unsafe-eval'` in `script-src`, though no source uses `eval` or `new Function`. This is a security cleanup outside the antislop gate.
- Mobile preview screenshot: the blank white frame in the mobile screenshot is a headless full-page capture artifact. The iframe has content, `srcdoc` is populated, and computed text is `#1f1d1a` on `#ffffff`.
