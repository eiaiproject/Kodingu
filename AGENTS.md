# Kodingu

Kodingu is a static learning site for HTML, CSS, and JavaScript. Each lesson explains one idea, then asks the learner to write code in the browser. There is no account, backend, or AI tutor.

The production site is plain HTML, CSS, and ES modules. It has no build step, framework, bundler, or runtime dependency. `package.json` exists only for local verification tooling. Keep it that way unless the task explicitly changes that constraint.

## Commands

- `npm run dev` starts the local server at `http://localhost:4173`. It reads `_headers`, so the browser runs the same CSP as production.
- `npm run verify` runs the data checks and drives Chromium through every lesson, challenge, project, and page. This is the main check before finishing.
- `npm run course-index` regenerates `assets/js/data/course-index.js` and the per-lesson modules under `assets/js/data/lessons/` after changing lesson content, titles, minutes, or XP.
- `npm run pages` regenerates the static reading pages in `lessons/` after editing lesson text.
- `npm run audit` runs the optional layout, contrast, and focus pass.
- `npm run sitemap` regenerates `sitemap.xml` after adding or removing content.

Node 22 or newer is required for the tooling.

## Where things live

- `assets/js/data/data.js` and the sibling `data-*.js` files are the source of truth for courses and lessons.
- `assets/js/data/course-index.js` and `assets/js/data/lessons/` are generated. Do not edit them by hand.
- `lessons/` is generated by `npm run pages`. Do not edit those files by hand.
- `assets/js/core/app.js` holds storage, chrome, SEO, and preview helpers.
- `assets/js/pages/` holds one controller per page.
- `assets/css/base.css` holds tokens, `assets/css/app.css` holds layout and components, and `assets/css/static.css` styles the reading pages.
- `assets/fonts/` holds the self-hosted woff2 files. `scripts/fetch-fonts.mjs` refreshes them.
- `scripts/` holds the generators and the verification harness.
- `README.md` explains the architecture, content workflow, and deploy setup.

## Rules

- Edit lesson content in the data files, then run `npm run course-index`, `npm run pages`, and `npm run sitemap`.
- Run `npm run verify` before calling a change done. If it fails, fix the cause instead of loosening the check.
- Keep progress data in `localStorage`. Any schema change needs a migration path for `kodingu.progress.v1`.
- Bump the cache name in `sw.js` when the shell changes.
- Do not add a build step or a runtime dependency to the site.
